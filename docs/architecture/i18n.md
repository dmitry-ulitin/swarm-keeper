# Languages (i18n)

November 21, 2026.

Decision: the app supports two languages from day one — **English and Russian**. Language is a personal member setting. English is the key and fallback language. This file collects the decisions for every layer; details are in [backend.md](backend.md), [authentication.md](authentication.md), [frontend.md](frontend.md) and the [design system](../design/README.md).

## Backend (NestJS)

- **User language** — the `user.locale` field (`en` | `ru`), returned by `GET /me` together with `uiSize`. On sign-up via invitation it is taken from `invitation.locale`; the inviter picks the invitation's language (their own by default).
- **API errors are codes with parameters**, never ready-made text: `{ "code": "invite.expired", "params": { ... } }`. Clients translate them.
- **Emails** (invitation, email verification, password reset) have `en` and `ru` templates; the language comes from `user.locale` or `invitation.locale`.
- **OCR** — `ocrmypdf -l rus+eng`.
- **Search** — two `tsvector` columns (`russian` and `english`) plus `pg_trgm` for names and typos.
- **Not translated:** whatever people typed — albums, captions, names, document metadata.

## Authentication (Better Auth)

- The email hooks (`sendVerificationEmail`, `sendResetPassword`, `sendInvitationEmail`) pick the template by `user.locale` or `invitation.locale`. 2FA is TOTP in an authenticator app and sends no email.
- The `locale` field is added to the user schema via `user.additionalFields` and to invitations via `invitation.additionalFields` (check against the organization plugin docs when installing).
- `appName`, `rpName` and `issuer` are "Swarm Keeper" in both languages: the name is never translated.

## Web (Angular)

- Transloco with per-feature JSON loaded lazily; ICU MessageFormat for plurals; dates, numbers and sizes via `Intl`.
- Errors: our API codes (`errors.<code>`), Better Auth codes and our auth codes `INVITE_REQUIRED`, `TWO_FACTOR_REQUIRED` (`errors.auth.<code>`); document types are stored as codes and translated via `documents.type.<code>`.
- Before sign-in the language comes from `navigator.languages` (otherwise English), after sign-in from `locale` in `/me`; it switches without a reload.
- CI checks that every key exists in `en` and `ru`; Playwright runs key screens in both languages.

## Design system and the native app

- The bilingual glossary (Family/Семья, Timeline/Лента, Trash/Корзина, etc.) is in the "Interface language" section of the design system; it is binding for the web, the native app and emails.
- No fixed widths: Russian strings are 20–30% longer than English.
- The native app uses its own translation system (String Catalogs / `strings.xml` or ARB) with the same terms.
- **Translations are stored as JSON files in the repository**; no separate translation service (Tolgee, Weblate) is needed (decided November 21, 2026).
