# Auth Core (3a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Better Auth runs inside the API on snake_case, UUIDv7 tables from our migrations; `/api/auth/*` is mounted behind a global guard; sign-up works only from an invitation; `pnpm db:seed` creates the first owner and family.

**Architecture:** `apps/api/src/modules/identity/` owns everything auth: `auth-env.ts` (env → settings), `snake-case-schema.ts` (the one place that replaces the broken `casing` option), `create-auth.ts` (the Better Auth instance over `db.withoutPlugins()`), `invite-only.ts` (the database hooks), `mailer.ts`, and `identity.module.ts` (`AuthModule.forRootAsync`). The seed is a small script built with the API.

**Tech Stack:** `better-auth` 1.7.27, `@better-auth/passkey` 1.7.27, `@thallesp/nestjs-better-auth` 2.8.0, `auth` 1.7.27 (CLI, dev), Kysely 0.29, NestJS 12 (Express), Vitest 5, supertest.

**Spec:** `docs/superpowers/specs/2026-11-23-auth-core-design.md`

## Global Constraints

- Plugins: organization, passkey, twoFactor, bearer only. No social providers. `cookieCache` off. `telemetry: { enabled: false }`.
- `requireEmailVerification: true`, `minPasswordLength: 12`, `session.expiresIn` 30 days, `session.updateAge` 1 day, `rateLimit: { enabled: true, storage: 'database' }`, `allowUserToCreateOrganization: false`, `invitationExpiresIn` 7 days, `requireEmailVerificationOnInvitation: true`.
- Every Better Auth table and column name is snake_case; IDs are `uuid` with `default uuidv7()`.
- Imports from `better-auth` subpaths as the 1.7.27 docs show; option names checked against the installed `.d.mts`, never guessed.
- Versions exact. `better-auth` stays in the catalog; new runtime deps of API code also go into `apps/worker/package.json` (CLAUDE.md rule).
- Error code for a sign-up without an invitation: `INVITE_REQUIRED`.
- ESM, `.js` suffixes, Conventional Commits.

## Review Focus

1. An expired, cancelled or already accepted invitation must not let anyone sign up — Task 3 test table covers `expired`, `canceled`, `accepted`.
2. An invitation for one email used with a different email in the sign-up body must be rejected, not create an unverified account — Task 3 test.
3. A Better Auth update that adds a field must fail loudly instead of writing a camelCase column — Task 1 test asserts every model and field name in `getAuthTables` of the final options is snake_case.
4. Production without `BETTER_AUTH_SECRET` must fail at startup — Task 1 `authEnv` test.
5. Running `pnpm db:seed` twice must not create a second owner or family — Task 4 test.

**Interfaces:**
- `authEnv(env = process.env): { secret: string; baseURL: string; passkeyRpId: string }` — dev defaults `baseURL = 'http://localhost:4200'`, `passkeyRpId = 'localhost'`, a fixed dev secret (≥ 32 chars, marked dev-only); in production `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL` are required (`Error('BETTER_AUTH_SECRET is required in production')` etc.).

- `interface Mailer { invitation(input: { email: string; url: string; locale: string }): Promise<void>; verifyEmail(input: { email: string; url: string }): Promise<void>; resetPassword(input: { email: string; url: string }): Promise<void> }`, `class LoggingMailer implements Mailer` (Nest `Logger`, logs the URL), token `MAILER`.
- `createAuth(db: Database, env: ReturnType<typeof authEnv>, mailer: Mailer)` → the `betterAuth(...)` instance; `type Auth = ReturnType<typeof createAuth>`. Hooks are added in Task 3; this task leaves `databaseHooks` out.
