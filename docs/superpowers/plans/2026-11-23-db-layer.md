# Database Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The API and the worker get a typed Kysely connection to PostgreSQL, migrations run from `pnpm db:*`, table types are generated, and API tests run against a freshly migrated `swarm_keeper_test`.

**Architecture:** `apps/api/src/database/` is a Sheriff module of its own (tag `api:infra:database`) that every API module may import. It holds the URL helpers, a `createDatabase` factory, the migrator and a global `DatabaseModule`. Migrations are TypeScript files in `apps/api/migrations/`, run by `kysely-ctl` from the CLI and by Kysely's `Migrator` in the Vitest global setup.

**Tech Stack:** `kysely` 0.29.9, `pg` 8.23.1, `kysely-ctl` 0.22.0, `kysely-codegen` 0.20.0, `@types/pg` 8.23.1, PostgreSQL 18 (dev compose), NestJS 12, Vitest 5.

**Spec:** `docs/superpowers/specs/2026-11-23-db-layer-design.md`

## Global Constraints

- Versions pinned exactly through the `catalog:` in `pnpm-workspace.yaml`: `kysely: 0.29.9`, `pg: 8.23.1`, `@types/pg: 8.23.1`; `kysely-ctl: 0.22.0`, `kysely-codegen: 0.20.0` (api devDependencies, exact).
- Dev default URL: `postgres://swarm:swarm@127.0.0.1:5432/swarm_keeper`. Test database name: `swarm_keeper_test`.
- snake_case in the database, camelCase in TypeScript via `CamelCasePlugin`; codegen with `--camel-case`.
- New tables default IDs to `uuidv7()` (Postgres 18 native). No table is created in this plan.
- No Better Auth or archive tables, no RLS, no `SET LOCAL`.
- ESM, `nodenext`, `.js` import suffixes. Commits follow Conventional Commits.
- Option names of `kysely-ctl` and `kysely-codegen` are checked against the installed versions (`--help`, their README in `node_modules`), never guessed.

## Review Focus

1. In production, a missing `DATABASE_URL` must fail at startup, not silently connect with the dev credentials — `databaseUrl` test in Task 1.
2. `app.close()` (SIGTERM) must end the pool, so the process exits instead of hanging on idle connections — Task 2 test checks a query fails after close.
3. The test setup must never drop the dev or any non-test database: it refuses a target whose name is not `swarm_keeper_test` — Task 1 `testDatabaseUrl` test.
4. A migration's `down` must undo its `up`, so `db:migrate:down` on dev is safe — Task 1 round-trip test.
5. Booting the worker or the API without Postgres running must not crash at import or module init (the pool connects lazily); only queries fail — Task 2 test constructs the module with an unreachable URL.
