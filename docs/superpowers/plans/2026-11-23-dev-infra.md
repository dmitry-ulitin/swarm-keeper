# Dev Infrastructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `pnpm infra:up` brings up PostgreSQL and Garage (S3) for local development, idempotently, and the Angular dev server proxies `/api` to the host-run API.

**Architecture:** A root `compose.yaml` (project `swarm-keeper-dev`) runs only infrastructure. A host-side shell script bootstraps Garage through `docker compose exec garage /garage …`. A smoke script `infra/dev/check.sh` is the test for every task: it asserts the running stack and grows one section per task.

**Tech Stack:** Docker Compose v5, `postgres:18.7-alpine`, `dxflrs/garage:v2.5.0`, POSIX `sh`, `amazon/aws-cli` (pinned at execution time, latest stable tag) for the S3 round trip, Angular dev-server proxy.

**Spec:** `docs/superpowers/specs/2026-11-23-dev-infra-design.md`

## Global Constraints

- Development only. No app images, Caddy, HTTPS, Mailpit, worker media tools or Playwright.
- Compose project name `swarm-keeper-dev`; file `compose.yaml` at the repo root.
- Ports bound to `127.0.0.1` only. Defaults: Postgres `5432`, Garage S3 `3900`; overridable with `POSTGRES_PORT` and `S3_PORT`.
- Data in named volumes `postgres-data`, `garage-meta`, `garage-data`.
- Every variable has a dev default, so everything works without `.env`. If `.env` exists, scripts and Compose read it.
- Dev defaults: `POSTGRES_USER=swarm`, `POSTGRES_PASSWORD=swarm`, `POSTGRES_DB=swarm_keeper`, `DATABASE_URL=postgres://swarm:swarm@127.0.0.1:5432/swarm_keeper`, `S3_ENDPOINT=http://127.0.0.1:3900`, `S3_REGION=garage`, `S3_BUCKET=swarm-keeper`, `S3_ACCESS_KEY_ID=GK` + 24 hex chars, `S3_SECRET_ACCESS_KEY` = 64 hex chars (fixed dev values, chosen once and written in `.env.example`).
- Garage commands and `garage.toml` keys are checked against the v2.5.0 docs/CLI help (`docker compose exec garage /garage help`), never guessed.
- Scripts are POSIX `sh`, executable, `set -eu`.
- Commits follow Conventional Commits; commit steps run as part of the approved plan.

## Review Focus

1. A second `pnpm infra:up` on an initialized stack must succeed without errors (layout, key and bucket already exist) — Task 2 check runs `infra:up` twice.
2. `pnpm infra:reset` followed by `pnpm infra:up` must rebuild a working stack from empty volumes — Task 2 Step 6.
3. No `.env` present must still work with defaults — every `check.sh` run in this plan happens without `.env`.
4. Services must not listen on non-loopback interfaces — Task 1 check asserts `docker compose port` returns `127.0.0.1:…`.
5. `infra:up` must fail loudly, not hang or half-succeed, when a service never becomes healthy — `docker compose up --wait --wait-timeout 60` and `set -eu` in the script; Task 1 Step 5 checks the exit code is non-zero with a broken healthcheck, then restores it.

### Task 1: PostgreSQL service, env and root scripts

**Files:**
- Create: `compose.yaml`, `infra/dev/check.sh`
- Modify: `package.json` (scripts), `.env.example`

**Interfaces:**
- Produces: root scripts `infra:up` = `docker compose up -d --wait --wait-timeout 60 && sh infra/dev/garage-init.sh` (the init part is added in Task 2; in Task 1 it is only the `up` part), `infra:down` = `docker compose down`, `infra:reset` = `docker compose down -v`, `infra:logs` = `docker compose logs -f`, `infra:check` = `sh infra/dev/check.sh`.
- Produces: `check.sh` sections are functions `check_postgres`, `check_garage`, `check_proxy`, called in order; each prints `ok: <what>` or exits non-zero with `FAIL: <what>`.

- [ ] **Step 1: Write the failing check** `check_postgres` in `check.sh`:
  - `docker compose ps --format json postgres` shows `Health` = `healthy`;
  - `docker compose port postgres 5432` starts with `127.0.0.1:`;
  - `docker compose exec -T postgres psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -tAc 'select 1'` prints `1`;
  - `… -tAc 'create extension if not exists pg_trgm; select extname from pg_extension where extname = $$pg_trgm$$'` prints `pg_trgm`.
- [ ] **Step 2:** `pnpm infra:check`. Expected: FAIL (no compose file / service).
- [ ] **Step 3:** Write `compose.yaml` with `name: swarm-keeper-dev`, service `postgres` (image, env with `${VAR:-default}`, port `127.0.0.1:${POSTGRES_PORT:-5432}:5432`, volume `postgres-data:/var/lib/postgresql`, healthcheck `pg_isready -U … -d …`, interval 2s, retries 30). Add the root scripts. Extend `.env.example` with every variable from Global Constraints, grouped with comments, keeping `NODE_ENV` and `PORT`.
- [ ] **Step 4:** `pnpm infra:up && pnpm infra:check`. Expected: `ok:` lines for all four postgres checks, exit 0.
- [ ] **Step 5: Failure path.** Temporarily change the healthcheck to `exit 1`, run `pnpm infra:up`; expected: non-zero exit within ~60 s. Restore, `pnpm infra:up` again, expected: exit 0.
- [ ] **Step 6: Commit** `chore(infra): add Postgres to dev compose`.

### Task 2: Garage service and bootstrap

**Files:**
- Create: `infra/dev/garage.toml`, `infra/dev/garage-init.sh`
- Modify: `compose.yaml`, `package.json` (`infra:up` gets `&& sh infra/dev/garage-init.sh`), `infra/dev/check.sh`

**Interfaces:**
- Consumes: `check.sh` structure from Task 1.
- Produces: bucket `$S3_BUCKET` reachable at `$S3_ENDPOINT` with key `$S3_ACCESS_KEY_ID` / `$S3_SECRET_ACCESS_KEY`, region `$S3_REGION`.
- `garage.toml`: single node, `replication_factor = 1`, `db_engine = "lmdb"`, S3 API on `[::]:3900` with `s3_region = "garage"`, RPC on 3901 with a fixed dev `rpc_secret`, admin API on 3903 with a fixed dev token. A header comment says every secret in it is dev-only.
- `garage-init.sh` loads `.env` when present, applies the S3 defaults from Global Constraints, and each step skips when already done:
  - assign a layout to the single node and apply it, only if the layout has no nodes;
  - import the key, only if `key info` cannot find it;
  - create the bucket, only if `bucket info` cannot find it;
  - grant `--read --write --owner` (repeating it is harmless).

- [ ] **Step 1: Write the failing check** `check_garage`:
  - the `garage` service is `healthy`;
  - `docker compose port garage 3900` starts with `127.0.0.1:`;
  - an `amazon/aws-cli:<pinned>` container on network `swarm-keeper-dev_default` with the dev key and `--endpoint-url http://garage:3900 --region garage` runs `s3 cp` of a temp file to `s3://$S3_BUCKET/check/roundtrip.txt`, copies it back, and the content matches; then it deletes the object.
- [ ] **Step 2:** `pnpm infra:check`. Expected: postgres `ok:`, then `FAIL:` for garage.
- [ ] **Step 3:** Add service `garage` to `compose.yaml`: image, `infra/dev/garage.toml` mounted read-only at `/etc/garage.toml`, volumes `garage-meta` and `garage-data`, port `127.0.0.1:${S3_PORT:-3900}:3900`, healthcheck with the CLI (`["CMD", "/garage", "status"]` or the v2.5.0 equivalent).
- [ ] **Step 4:** Write `garage-init.sh` and hook it into `infra:up`.
- [ ] **Step 5:** `pnpm infra:up && pnpm infra:up && pnpm infra:check`. Expected: both `up` runs exit 0, all checks `ok:`.
- [ ] **Step 6:** `pnpm infra:reset && pnpm infra:up && pnpm infra:check`. Expected: exit 0, all checks `ok:`.
- [ ] **Step 7: Commit** `chore(infra): add Garage S3 storage to dev compose`.
